Schema Field Extraction Flow

현재 구현은 field 하나마다 호출하지 않고, schema field를 full-page group과 region group으로 나눠 호출합니다. region이 없는 field는 full-page group에서, region_id가 있는 field는 같은 region_id끼리 묶여 추론됩니다.

VLM Calls Per Document

groups 호출 수는 full-page group 1회(필요 시) + 사용 중인 region group 수입니다.

Prompt Scope

Group fields 각 호출에는 해당 group에 속한 field의 key, format, description만 들어갑니다.

Structured Output

Group keys 동적 JSON schema는 해당 group의 field key만 required로 요구하고, backend가 group 결과를 merge합니다.

1. 현재 실제 처리 흐름

schema가 이미 저장되어 있고, 사용자가 Extract를 누른 뒤 한 document job이 실행되는 기준입니다.

Step 1

Schema Version Load

DB에서 schema version JSON을 읽고 fields, regions를 복원합니다.

fields[10] regions[k]
→

Step 2

Image Inputs Build

필드 구성에 따라 full page, masked context, crop 이미지를 구성합니다.

full pages if needed masked page crop
→

Step 3

Grouped Structured VLM Invoke

full-page group과 region group별로 별도 HumanMessage를 만들고 각각 invoke합니다.

structured_llm.invoke × groups
→

Step 4

Per-field Validation

모델 응답 이후에만 field별 타입 검증, warning, normalization을 수행합니다.

validate field A validate field B ...

2. Field 1개는 어떻게 추출되는가?

field는 자신이 속한 group 호출에만 들어갑니다. region이 없는 field는 full-page group에 들어가고, region_id가 있는 field는 같은 region_id를 가진 field들과 함께 region group에 들어갑니다. 

Prompt:
Full-page group prompt:
- field_1 (string): description...
- field_2 (date): description...

Region group prompt:
- field_3 (string): description...
- field_4 (bool): description...

Output schema:
{
  "type": "object",
  "required": ["group_field_1", "group_field_2"],
  "properties": {
    "group_field_1": {"value", "page", "evidence", "confidence"},
    "group_field_2": {"value", "page", "evidence", "confidence"}
  }
}

3. Region이 있는 field는 어떻게 다른가?

region_id가 있는 field는 같은 region_id끼리 별도 호출됩니다. 그 호출에는 해당 region의 masked context와 crop만 들어가고, output schema도 그 region field만 포함합니다. 

Field instruction:
- name (string): 우측 하단의 이름.
  Use masked full page context and crop
  for region_id "region_1".

Image inputs for region_1:
1. masked full page context
2. cropped region image

4. 호출 수와 이미지 입력 수

질문한 케이스별 현재 동작입니다.

Case VLM 추론 횟수 이미지 입력 비고
field 10개, region 없음 1번 전체 page images 모든 field가 full-page group 하나에 들어갑니다.
field 10개, region 1개, 나머지는 full page 2번 full-page 호출: 전체 page images / region 호출: region_1 masked context + crop full-page fields 1회와 region_1 fields 1회로 나눠 structured output을 받은 뒤 merge합니다.
field 10개가 모두 region 1개를 공유 1번 region_1 masked context + region_1 crop full-page field가 없으면 전체 page images는 별도로 넣지 않습니다.
field 10개, unique region k개, full-page field 있음 k + 1번 full-page 호출 1회 + region별 masked context/crop 호출 k회 사용 중인 region k개와 full-page field 유무에 따라 호출 수가 늘어납니다.
batch 문서 N개 문서별 group 수 × N 각 문서별로 위 규칙 적용 문서별 extraction job이 생기며, 각 job 내부에서 full-page/region group 호출을 수행합니다.

5. 현재 코드에서 호출 경계

backend/app/extraction.py schema fields와 regions를 로드하고 full-page/region group별 request를 만든 뒤 group마다 extract_with_vlm을 호출합니다. 
fields = [FieldDefinition(...)]
regions = [SchemaRegion(...)]
requests = _build_extraction_requests(...)

raw_values = {}
for request in requests:
  group_values = extract_with_vlm(
    request["fields"],
    image_inputs=request["image_inputs"]
  )
  raw_values.update(group_values)

6. 현재 코드에서 VLM 호출

backend/app/vlm.py 각 group의 prompt, image content, output schema를 묶어서 structured_llm.invoke를 실행합니다. 
content = _build_multimodal_content(
  _build_user_prompt(fields),
  image_inputs
)

structured_llm = llm.with_structured_output(
  output_schema,
  method="json_schema",
  strict=True
)

response = structured_llm.invoke([...])

7. 현재 방식의 의미

장점 full-page field와 region field가 서로 덜 오염됩니다. 같은 region에 속한 field끼리는 같은 crop 문맥을 공유합니다. 각 group의 structured output schema가 해당 field만 강제합니다.
주의점 사용 중인 region이 많으면 호출 수와 비용이 증가합니다. region field가 full-page 문맥을 필요로 하면 masked context 품질이 중요합니다. 같은 group 안에서는 한 field의 어려움이 같은 group 응답 품질에 영향을 줄 수 있습니다.
현재는 full-page fields 1회 + region별 1회 구조입니다. 다음 단계로 더 강하게 분리하려면 field별 1회 모드를 추가할 수 있지만, 호출 수와 비용은 더 증가합니다.
