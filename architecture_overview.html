1. 기능 맵

Enabled Raw Data Extractor

DOCX/XLSX/PPTX/PDF를 업로드해 좌측 PDF preview와 우측 HTML 추출 결과를 보여줍니다.

  • 이미지 추출 기본 on
  • 수식 추출 기본 off
  • Office HTML은 원본 파일에서 직접 파싱
Enabled Key Information Extractor

PDF/이미지/DOCX/PPTX를 페이지 이미지로 변환한 뒤, 사용자 schema 기준으로 VLM structured output을 수행합니다.

  • schema field: key name, description, output format
  • output format: string, float, date, bool
  • review, correction, JSON/CSV export
Coming Soon OCR

단순 OCR 기능 예정입니다. 현재 UI에서는 disabled 카드로만 표시합니다.

Coming Soon Intelligence Parse

문서를 구조적으로 이해하고 지능형 parsing을 수행하는 확장 기능 예정입니다.

2. 시스템 구조

Frontend

  • Vite + React + TypeScript
  • Home: 기능 선택, Setting modal
  • Raw workspace: PDF iframe + HTML iframe
  • KIE workspace: document viewer + schema/review panel
  • Recent, Archive, Batch, Audit UI

Backend

  • FastAPI API server
  • PyMuPDF page rasterization
  • LibreOffice headless PDF preview conversion
  • Raw parsers: mammoth, openpyxl, python-pptx, PyMuPDF
  • LangChain structured output VLM integration

Storage

  • SQLite: backend/digitize_documents.db
  • Document files: backend/storage/documents/
  • Raw files: backend/storage/raw/
  • Runtime config: root .env
  • No secret is sent to frontend
중요한 설계 기준 Raw Data Extractor에서 Office 파일의 PDF 변환은 preview 용도입니다. HTML 정보 추출은 변환된 PDF가 아니라 원본 DOCX/XLSX/PPTX에서 직접 수행합니다.

3. 처리 흐름

Raw Data Extractor

1. Upload

DOCX, XLSX, PPTX, PDF 업로드

2. Save Original

backend/storage/raw/{id}/original.ext

3. PDF Preview

Office는 LibreOffice로 preview.pdf 생성, PDF는 copy

4. Original Parser

원본 파일에서 text/table/image/formula HTML 추출

5. Review

좌측 PDF preview, 우측 HTML preview

Key Information Extractor

1. Upload

PDF, PNG, JPG, JPEG, DOCX, PPTX 업로드

2. Page Image

PDF/Office는 page PNG로 rasterize, image는 1-page 처리

3. Schema

사용자가 key_name, description, output_format 지정

4. VLM

LangChain with_structured_output으로 schema 기반 추출

5. Validate/Export

타입 검증, warning, correction, JSON/CSV export

4. 데이터 모델

SQLite local DB에 저장되는 주요 table과 책임입니다.

Table 핵심 필드 역할 관계
documents id, filename, mime_type, page_count, storage_path, document_type, language KIE 입력 문서 metadata 1:N document_pages, 1:N extraction_jobs
document_pages document_id, page_number, image_path, width, height VLM에 전달할 page image 목록 N:1 documents
schemas name, display_name, description, current_version, is_template, pinned 사용자 extraction schema header 1:N schema_versions, 1:N extraction_jobs
schema_versions schema_id, version, schema_json schema 변경 이력과 실제 field definition snapshot N:1 schemas
extraction_jobs document_id, schema_id, schema_version, status, result_id KIE extraction 실행 단위 N:1 documents, N:1 schemas, 1:1 extraction_results
extraction_results raw_model_output, validated_output, corrected_output, warnings, reviewed_fields structured output 결과, 검증 결과, 사용자 correction 저장 1:1 extraction_jobs
raw_extractions filename, source_format, storage_path, pdf_path, html_path, status, warnings Raw Data Extractor 결과 metadata 독립 실행 단위
batches / batch_items schema_id, total_count, document_id, job_id, filename 동일 schema로 여러 문서 KIE 처리 batch_items가 document/job 연결
export_presets schema_id, name, fields_json JSON/CSV export field mapping preset optional N:1 schemas
audit_events entity_type, entity_id, action, message, metadata_json 업로드, schema 변경, extraction, export 등 이력 entity_type/entity_id polymorphic reference

7. 핵심 계약

Schema Field Contract
  • key_name: 사용자가 보는 결과 key. 한글 가능
  • description: 해당 값을 문서 어디서/어떻게 찾을지 알려주는 field-level instruction
  • output_format: string, float, date, bool 중 하나
Structured Output Contract
  • VLM은 LangChain with_structured_output을 통해 schema object를 반환해야 함
  • stringified JSON 응답은 실패로 처리
  • 사용자 schema에 없는 key는 저장하지 않음
  • 누락, 타입 불일치, 낮은 confidence는 warning/review 대상으로 이동
Raw HTML: 원본 Office/PDF 파서 기반 KIE VLM 입력: page image data URL Secret: backend .env only Local-first MVP: SQLite + filesystem
