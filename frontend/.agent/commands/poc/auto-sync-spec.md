# Command: auto-sync-spec

> 구현 도중 AI가 Spec과 코드의 불일치를 감지했을 때 자동으로 실행하는 절차서입니다.
> 사용자 호출 없이 `implement-poc` command 내에서 자동으로 트리거됩니다.
> 변경 보고가 필요한 경우 `sync-spec` command를 사용하세요.

---

## 자동 트리거 조건

아래 상황 중 하나라도 해당되면 즉시 실행합니다. 사용자에게 묻지 않습니다.

```
- 구현 중 Spec에 정의된 API 응답 구조와 실제 API가 다름을 발견
- Spec의 Component Tree와 실제 구현 구조가 달라짐
- Spec에 없는 Edge Case를 코드에서 처리해야 하는 상황
- Spec의 Goals 중 하나가 구현 불가능하거나 범위가 바뀜
- 요건 변경 요청을 받았을 때 ("~를 바꿔줘", "~는 빼줘")
```

---

## Step 1 — 불일치 감지 즉시 보고

자동 트리거 조건이 감지되면 구현을 멈추고 즉시 보고합니다.

> 🟢 채비: Spec과 다른 부분을 발견했습니다.
>         구현을 잠시 멈추고 Spec을 업데이트합니다.
>
>         감지된 불일치:
>         - {불일치 내용 한 줄 설명}

---

## Step 2 — Spec 자동 업데이트

사용자 확인 없이 즉시 Spec을 수정합니다.

### 자동 처리 범위 (확인 없이 진행)

```
✅ API 응답 구조 수정 (섹션 4)
✅ Component Tree 수정 (섹션 3)
✅ Edge Case 추가 (섹션 5)
✅ Testing 시나리오 추가 (섹션 6)
✅ 변경 이력 주석 추가
```

### 사용자 확인 필요 (자동 처리 불가)

```
🚫 Goals 항목 제거
🚫 Non-Goals 항목 추가
🚫 구현 범위 축소
```

위 항목이 필요한 경우 자동 처리를 멈추고 사용자에게 확인을 요청합니다.

> 🟢 채비: Goals 변경이 필요합니다. 확인해주세요.
>
>         제안:
>         - Goals에서 제거: "{항목}"
>         - 이유: {이유}
>
>         동의하시면 "확인"이라고 말씀해 주세요.

### 업데이트 규칙

- 상태를 `approved` → `draft`로 변경
- 수정한 섹션 상단에 변경 이력 주석 추가

```md
<!-- auto-sync {YYYY-MM-DD}: {한 줄 요약} -->
```

- [ ] 수정 범위가 자동 처리 가능한 항목인가?
- [ ] 변경 이력 주석이 추가되었는가?

---

## Step 3 — 구현 재개

Spec 업데이트 완료 후 즉시 구현을 재개합니다.

> 🟢 채비: Spec 업데이트 완료. 구현을 계속합니다.

구현 완료 후 `implement-poc` Step 6 전체 검증에서 Spec과 코드의 일치 여부를 최종 확인합니다.

---

## auto-sync vs sync-spec 비교

| 항목 | auto-sync-spec | sync-spec |
|------|---------------|-----------|
| 트리거 | AI 자동 감지 | 사용자 명시 호출 |
| 목적 | 구현 중 불일치 즉시 수정 | 진행 중 변경사항 구조화 보고 |
| 사용자 개입 | Goals 변경 시에만 | 항상 (승인 필요) |
| 실행 시점 | implement 도중 | implement 전후 언제든 |
| 보고 형식 | 간략 (불일치 내용만) | 상세 (3개 영역 전체) |
