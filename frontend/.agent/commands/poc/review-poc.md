# Command: review-poc

> 구현 완료 후 사용자 검증 → 코드 리뷰 → 완료 보고를 담당하는 절차서입니다.
> `implement-poc` command의 Step 6 완료 후 채비가 자동으로 호출합니다.
> 직접 호출도 가능합니다.

---

## 전체 흐름

```
[1] 사용자 기능 검증 요청
    ↓
[2] CodeReviewer + PerfReviewer 실행
    ↓
[3] 채비: 리뷰 결과 통합 안내 + 수정 선택
    ↓
[5] 수정 또는 건너뛰기
    ↓
[6] 완료 보고
```

---

## [1] 사용자 기능 검증 요청

> `implement-poc` Step 7에서 진입한 경우, 검증 안내는 이미 끝났으므로 **[2]로 바로 이동**합니다.
> `review-poc`를 **직접 호출**한 경우에만 아래 검증 안내를 진행합니다.

> **dev server는 채비가 직접 실행합니다.** 사용자가 명령어를 입력하지 않습니다.
> 서버가 떠 있지 않으면 백그라운드로 `pnpm dev`를 실행하고, 이미 실행 중이면 기존 주소를 안내합니다.
> (이 프로젝트는 pnpm 전용입니다. `npm`/`yarn`을 쓰지 않습니다.)

---
🟢 채비: 구현이 완료되었습니다. 직접 확인해주세요:)

        화면: http://localhost:5173

        확인 항목:
        {docs/tech-specs/{feature}.spec.md의 Goals 항목을 체크리스트로 변환}
        - [ ] {Goal 1}
        - [ ] {Goal 2}
        - [ ] {Goal 3}

        모두 확인되셨으면 "확인 완료"라고 말씀해 주세요.
        문제가 있으면 어떤 부분인지 알려주세요.

---

### 분기

- **"확인 완료"** → [2]로 이동
- **문제 발견** → 해당 Step으로 돌아가 수정 → [1] 재실행
- **"건너뛰기"** → [2]로 이동 (검증 미완료 상태로 기록)

- [ ] 사용자 확인이 완료되었는가?

---

## [2] 코드 품질 리뷰

`subagents/reviewers/poc/code-reviewer.md`를 참조하여 이번 구현에서 생성/수정된 파일을 리뷰합니다.

결과를 아래 형식으로 수집합니다.

```
QA 리뷰 결과 (내부 수집 — 사용자에게 바로 출력하지 않음)

| ID | 분류 | 파일 | 원인 | 설명 |
|----|------|------|------|------|
| QA-01 | 🔴 Critical | {파일} | {규칙} | {설명} |
| QA-02 | 🟡 Warning  | {파일} | {규칙} | {설명} |
---
| QA-03 | 🟢 Suggest  | {파일} | {규칙} | {설명} |

---
```

리뷰 항목이 없으면 `QA: 이슈 없음`으로 기록합니다.

- [ ] code-reviewer 리뷰가 완료되었는가?

---

## [3] 성능 리뷰

`subagents/reviewers/poc/perf-reviewer.md`를 참조하여 동일한 파일을 리뷰합니다.

```
PERF 리뷰 결과 (내부 수집)

| ID | 분류 | 파일 | 원인 | 설명 |
|----|------|------|------|------|
| PERF-01 | 🔴 Critical    | {파일} | {규칙} | {설명} |
| PERF-02 | 🟡 Significant | {파일} | {규칙} | {설명} |
---
| PERF-03 | 🟢 Minor       | {파일} | {규칙} | {설명} |

---
```

리뷰 항목이 없으면 `PERF: 이슈 없음`으로 기록합니다.

- [ ] perf-reviewer 리뷰가 완료되었는가?

---

## [4] 채비: 리뷰 결과 안내

QA + PERF 결과를 합산하여 사용자에게 안내합니다.
이슈가 없으면 [6] 완료 보고로 바로 이동합니다.

---
🟢 채비: 코드 리뷰가 완료되었습니다.

        개선 포인트를 확인해주세요:

        | ID | 기준 | 내용 | 중요도 |
        |----|------|------|--------|
        | QA-01 | 코드 품질 | {쉬운 설명} | 🔴 필수 |
        | QA-02 | 코드 품질 | {쉬운 설명} | 🟡 권장 |
        | PERF-01 | 성능 | {쉬운 설명} | 🟡 권장 |
        | PERF-02 | 성능 | {쉬운 설명} | 🟢 선택 |

        수정할 ID를 알려주세요. (예: "QA-01, PERF-01")
        건너뛰려면 "건너뛰기" — 수정 없이 바로 완료 보고로 넘어갑니다.

---

### 설명 작성 원칙

비FE 개발자도 이해할 수 있는 수준으로 작성합니다.

```
❌ "useCallback 누락으로 인한 불필요한 리렌더링 발생"
✅ "버튼을 클릭할 때마다 화면이 불필요하게 다시 그려집니다 (성능 저하)"

❌ "any 타입으로 인한 타입 안전성 저하"
✅ "타입이 지정되지 않아 나중에 오류를 찾기 어렵습니다"
```

🔴 Critical/필수 항목은 반드시 수정을 권장합니다.
---
PoC 맥락에서 🟢 선택 항목은 건너뛰어도 무방함을 명시합니다.

---

### [4-1] 개선 포인트를 Tech Spec에 기록 (필수)

QA/PERF로 도출된 개선 포인트를 `docs/tech-specs/{feature}.spec.md` **하단의 `## 개선 포인트` 섹션**에 누적 기록합니다. (섹션이 없으면 새로 만든다)

```markdown
## 개선 포인트

| ID | 기준 | 내용 | 중요도 | 상태 |
|----|------|------|--------|------|
| QA-01 | 코드 품질 | {설명} | 🔴 필수 | 대기 |
| PERF-01 | 성능 | {설명} | 🟡 권장 | 대기 |
```

- 상태 값: `대기` → (수정 진행) → `완료` / `건너뜀`
- [5]에서 항목을 수정하거나 건너뛸 때마다 이 표의 **상태를 갱신**합니다.

---

## [5] 수정 또는 건너뛰기

### 수정 선택 시

사용자가 지정한 ID 순서대로 수정합니다.

```
수정 순서:
1. 🔴 Critical 항목 먼저
2. 🟡 Warning / Significant
---
3. 🟢 Suggest / Minor

---
```

각 수정 완료 후:
```bash
pnpm exec vitest run
```
테스트가 통과하면 Tech Spec `## 개선 포인트` 표의 해당 항목 상태를 **`완료`**로 갱신하고 다음 ID로 이동합니다.

### 건너뛰기 선택 시

수정하지 않고 **바로 [6] 완료 보고로 이동**합니다. (추가 질문 없이 진행)
건너뛴 항목을 완료 보고의 미수정 항목으로 기록하고, Tech Spec `## 개선 포인트` 표의 상태를 **`건너뜀`**으로 갱신합니다.

---

## [6] 완료 보고

### [6-1] Tech Spec 일치도 확인 + Sync 여부 질문 (필수)

완료 보고 전에 **구현 결과가 `docs/tech-specs/{feature}.spec.md`와 일치하는지** 확인합니다.

- 일치하면 → 그대로 [6-2]로 진행
- **차이가 있으면** → 사용자에게 sync 여부를 묻고 답을 기다립니다.

```
🟢 채비: 구현이 Tech Spec과 일부 달라요.
        - {차이 항목 1}
        - {차이 항목 2}

        Spec을 현재 구현에 맞춰 동기화할까요? ("sync" / "그대로 두기")
```

- **"sync"** → `sync-spec` command 실행 후 [6-2]로
- **"그대로 두기"** → 차이를 완료 보고에 명시하고 [6-2]로

### [6-2] E2E 체크리스트 최종 완성 (필수)

`plan-poc`에서 **이미 생성한** `docs/poc-e2e-checklist-{feature}.md`를 **최종 점검·완성**합니다. (만약 없으면 `docs/poc-e2e-checklist-template.md`를 복사해 지금 생성)

- 게이트 통과 여부 / `## 7. 시간 측정`(리뷰 구간 포함) / `## 8. 결과물 퀄리티` 점수를 이번 사이클 실제 결과로 모두 채운다.
- 이 파일 경로를 [6-3] 보고의 링크로 포함한다 (완료 보고에 반드시 포함).

### [6-3] 완료 보고

> **다음 단계 제안은 아래 4가지로 제한합니다. Tech Spec을 벗어난 기능/개선 의견을 임의로 제시하지 않습니다.**
> 남은 개선 포인트 보기 / 추가 리뷰 진행 / Tech Spec 업데이트 / PoC 결과 보고

```
---
🟢 채비가 완료되었습니다 :)

        Tech Spec 목표 달성:
        - [x] {Goal 1}
        - [x] {Goal 2}
        - [ ] {미달성 Goal} ({사유})  ← 없으면 생략

        화면: http://localhost:5173   ← 클릭해서 확인하세요

        E2E 체크리스트: docs/poc-e2e-checklist-{feature}.md
        - 게이트 {N}/6 통과 · 퀄리티 {N}/30 · 종합 {PASS/조건부/FAIL}

        다음 단계: (아래 중에서 선택)
        - 남은 개선 포인트 보기
        - 추가 리뷰 진행
        - Tech Spec 업데이트
        - PoC 결과 보고

---
```
