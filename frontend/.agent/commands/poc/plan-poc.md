# Command: plan-poc

> PoC 개발의 시작점입니다. 사용자와 대화하며 Tech Spec을 작성하고, 프로젝트를 초기화합니다.
> 이 command는 아래 흐름을 순서대로 진행합니다.

```
[1] 인사 및 시작
    ↓
[2] 참조 문서 탐색
    ↓
[3] 요건 수집 (ref 있음 / 없음 분기)
    ↓
[4] Tech Spec 작성 → 사용자 승인
    ↓
[5] init-poc 자동 호출 (프로젝트 초기화 → build → dev server)
    ↓
[6] 구현 계획 수립 → 사용자 승인
    ↓
[7] implement-poc command로 이관
```

---

## [1] 인사 및 시작

PoC 개발 요청을 받으면 아래 메시지로 시작합니다.

```
---
🟢 채비: 안녕하세요! PoC 화면 개발을 돕는 에이전트 채비입니다. 채비 준비되었습니다:)

---

시작하기 전에 참조 문서를 확인하겠습니다.
docs/refs/ 폴더를 탐색합니다.
```

---

## [2] 참조 문서 탐색

`docs/refs/`를 아래 순서로 탐색합니다.

```
docs/refs/prd/      ← 기획서 / 요건 정의
docs/refs/api/      ← API 명세
docs/refs/design/   ← 화면 설계
docs/refs/notes/    ← 회의록 / 결정 메모
```

탐색 결과에 따라 분기합니다.

---

## [3-A] 참조 문서가 있는 경우

---
🟢 채비: `docs/refs/`에서 아래 문서를 확인했습니다.

- {파일명}: {한 줄 요약}
- {파일명}: {한 줄 요약}

문서를 기반으로 Tech Spec을 작성하겠습니다.
추가로 확인이 필요한 사항이 있으면 말씀해 주세요.
없으면 바로 진행합니다.

---

문서에서 파악되지 않은 항목만 질문합니다.

- 데모에서 반드시 동작해야 하는 핵심 흐름 (문서에 없는 경우)
- **데모 완료 기준** — 문서에 있더라도 반드시 사용자에게 재확인합니다
- 이번 범위에서 명시적으로 제외할 것 (Non-Goals)
- 문서 간 충돌이 있는 경우 → 사용자에게 기준 확인

> **완료 기준은 항상 재확인합니다.**
> ref 문서에 Goals가 작성되어 있더라도, 사용자가 직접 "이 화면이 동작하면 된다"를
> 측정 가능한 형태로 확인해야 Tech Spec의 Goals가 실제 데모와 일치합니다.

---

## [3-B] 참조 문서가 없는 경우

```
---
🟢 채비: docs/refs/에 참조 문서가 없습니다.

---
PoC 요건을 직접 여쭤보겠습니다.
```

아래 항목을 순서대로 확인합니다. 한 번에 전부 묻지 않고 대화 흐름으로 진행합니다.

```
1. 어떤 기능을 데모에서 보여주실 건가요?
2. 데모 완료 기준은 무엇인가요? ("이 화면이 동작하면 된다")
3. 이번에 만들지 않을 것은 무엇인가요?
4. 연동할 API가 있나요? 있다면 엔드포인트를 알려주세요.
```

---

## [4] Tech Spec 작성 → 승인

`.agent/templates/tech-spec.md` 기반으로 `docs/tech-specs/{feature-name}.spec.md`를 생성합니다.

### 작성 원칙

- ref 문서에서 추출한 내용은 출처 주석 표시
  ```md
  <!-- 출처: docs/refs/prd/20240115-feature-prd.md -->
  ```
- Non-Goals는 반드시 작성 (비워두지 않음)
- API 연동 없으면 섹션 4 삭제
- 섹션 6 (Testing) 최소 2개 이상 시나리오 작성

### 작성 완료 후 메시지

---
🟢 채비: Tech Spec 초안을 작성했습니다.

        파일: `docs/tech-specs/{feature-name}.spec.md`

        주요 내용:
        - Goals: {핵심 목표 1~3줄 요약}
        - Non-Goals: {제외 항목 요약}

        예상 결과:
        {데모 완료 시 사용자가 경험하게 될 것을 자연어로 1~3문장 서술}
        예) "이미지를 업로드하면 슬라이드 레이아웃 초안이 화면에 표시되고,
             다운로드 버튼을 누르면 PPTX 파일을 받을 수 있습니다."

        구현 범위:
        - 페이지 {N}개
        - feature {N}개
        - 주요 컴포넌트: {컴포넌트 목록}

        작성한 문서 파일을 꼭 확인해주세요~
        이대로 개발을 시작하면 될까요?

---

> **HARD GATE — 건너뛰지 마세요.**
> 사용자가 명시적으로 승인("네" / "진행" 등)하기 전까지 [5] init-poc로 넘어가지 않습니다.
> 사용자가 Spec을 읽고 답할 시간을 줍니다. 가정으로 자동 진행하지 않습니다.
> 수정 요청이 있으면 Spec을 고치고 다시 이 질문으로 돌아옵니다.

- [ ] 사용자가 Tech Spec을 명시적으로 승인했는가? (미승인 시 대기)
- [ ] 상태를 `draft` → `approved`로 변경했는가?

### Tech Spec 승인 직후 — E2E 체크리스트 먼저 생성

> **완료 보고 때 만드는 게 아니라, 지금 미리 만듭니다.**

`docs/poc-e2e-checklist-template.md`를 복사해 이번 사이클의 `docs/poc-e2e-checklist-{feature}.md`를 **즉시 생성**합니다.

- 이미 지난 구간(`인사 → PoC 시작`, `Tech Spec 작성`)의 소요 시간을 `## 7. 시간 측정` 표 cell에 먼저 기록합니다.
- 이후 **각 단계가 끝날 때마다** 게이트 통과 여부와 시간 표의 해당 구간 cell을 갱신합니다(init/구현/리뷰).
- 완료 보고(`review-poc` [6])에서 이 문서를 최종 점검하고 링크로 포함합니다.

- [ ] `docs/poc-e2e-checklist-{feature}.md`를 생성했는가?

---

## [5] init-poc 자동 호출

Tech Spec 승인 후 자동으로 `init-poc` command를 실행합니다.

---
🟢 채비: Tech Spec 작성이 완료되었습니다.

프로젝트 초기화를 시작합니다.
→ `init-poc` command 실행

---

`init-poc` command 참조: `.agent/commands/poc/init-poc.md`

- [ ] 프로젝트 초기화가 완료되었는가?
- [ ] build가 성공했는가?
- [ ] dev server가 정상 동작하는가?

init-poc 실패 시 → 에러 원인을 사용자에게 보고하고 해결 후 재시도합니다.

---

## [6] 구현 계획 수립 → 승인

프로젝트가 정상 동작하면 구현 계획을 수립합니다.

---
🟢 채비: 프로젝트가 정상적으로 동작합니다.

이제 구현 계획을 잡겠습니다.

---

Tech Spec 섹션 3 (Architecture) 기반으로 구현 순서를 결정합니다.

```
구현 순서:

[ ] 1. 타입 정의 — {위치}
[ ] 2. API 훅 — {위치}
[ ] 3. {핵심 컴포넌트} — {위치}
[ ] 4. 페이지 연결 + 라우트
[ ] 5. 최소 테스트

예상 테스트 파일:
[ ] {테스트 파일 목록}

승인하시면 구현을 시작합니다.
```

> **HARD GATE — 건너뛰지 마세요.**
> 사용자가 구현 계획을 명시적으로 승인하기 전까지 [7] implement로 넘어가지 않습니다.
> **"구현 시작해줘" / "바로 만들어줘" / "시작해!" 같은 직접 명령이 있어도 이 게이트를 우회하지 않습니다.** 구현 순서를 먼저 제시하고 승인을 받은 뒤에 진행합니다.

- [ ] 사용자가 구현 계획을 승인했는가? (미승인 시 대기)

---

## [7] implement로 이관

---
🟢 채비: 구현을 시작합니다.

`implement-poc` command를 참조하여 진행합니다.

---

`implement-poc` command 참조: `.agent/commands/poc/implement-poc.md`

---

## 전체 흐름 요약

```
/Chaebi 첫 호출
  → 인사 + 안내 메시지 출력 → 대기
  
/Chaebi PoC 시작해줘
  ↓
docs/refs/ 탐색
  ├─ 문서 있음 → 문서 기반 요건 파악 → 불명확한 것만 질문
  └─ 문서 없음 → 4가지 질문으로 요건 수집
  ↓
Tech Spec 작성 (docs/tech-specs/{name}.spec.md)
  ↓
사용자 승인
  ↓
init-poc 자동 실행
  └─ Vite 설치 → FSD 구조 생성 → @genai/ui 설치 → build → dev server
  ↓
구현 계획 수립
  ↓
사용자 승인
  ↓
implement 실행
```
